## なぜ必要か

プライバシーポリシー（`docs/legal/privacy-draft.md`）の**第10条（開示・訂正・利用停止・削除等の請求）と第11条（退会とデータの消去）**で、当社は削除・利用停止に応じることを会員に約束しています。**ところが、実際にどう対応するかの手順がありません。** 公開初日に削除請求が来たら、その場で調べながら手作業することになります。

あわせて、**このサイトはパスワードの自動リセットができません。** 登録に実在のメールアドレスを使わず `@phone.yingpin.app` という架空のアドレスを内部で組み立てているため、再設定メールが届きません（利用規約 第6条第2項にその旨を明記済み）。**復旧はスタッフの手作業が前提**ですが、その手順も未整備です。

### 内容1: 会員の削除・退会

- **消す対象**: `members`（`applications`・`favorites` は cascade で一緒に消えます）と、**Supabase Auth のユーザー（`auth.users`）の両方**。片方だけ消すと、ログインはできるのに会員情報が無い、あるいはその逆の壊れた状態になります
- 🔴 **職業安定法との衝突をどう捌くかが、この文書のいちばん重要な部分です。** 職業安定法第32条の15により**求人求職管理簿は2年間の保存義務**があります。削除請求に対して「即時・完全に全部消す」と応じると、**今度は職業安定法違反**になります。**保存義務の対象になる記録は保存期間が満了するまで分離して保管し、それ以外を消す**という整理にしてください。プライバシーポリシー第8条（保管期間）・確認論点リストの **B-5** と矛盾しないように書いてください
- Resend で既に送信済みの通知メール（スタッフ宛て）の扱いにも触れてください
- **削除したことの記録の残し方**（いつ・誰の依頼で・何を消して・何を残したか）

### 内容2: パスワードの再設定（スタッフ手動）

- **本人確認をどうするか。** 登録済みの WeChat ID を通じた申し出を受け、会員番号・氏名・生年月日を照合する運用をプライバシーポリシー第10条に書いています
- ⚠️ **このサイトには「電話番号を本当に持っている」ことの証明がありません**（SMS認証を使っていないため）。したがって**スタッフによる WeChat 本人確認（`verified` フラグ）が、本人性を担保する唯一の手段**です。この含意を手順書に明記してください
- Supabase の画面のどこを操作するか。**画面名は推測で書かず、実際の `docs/ops/supabase-auth-policy-guide.md` や `staff-registration-guide.md` の記述に合わせてください**
- 🚨 **SQL Editor で書いてよいのは手順書に載っているSQLだけ**、という既存の約束を踏襲してください

### 内容3: 「Confirm email は OFF のまま」という制約

`Confirm email` を ON にすると、架空のアドレス宛に確認メールが飛んで**新規登録が全員失敗**します。しかも `auth.users` の行だけ残るため、その電話番号がロックアウトされます。**触ってはいけない設定**として、この文書からも注意喚起してください（詳細は `docs/progress.md` §24 と `docs/ops/supabase-auth-policy-guide.md`）。

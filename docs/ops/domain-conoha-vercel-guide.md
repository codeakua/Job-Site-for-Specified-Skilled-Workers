## ✅ 手順0：ドメインそのものを守る設定（3つ・**2026-07-29 に対応済み**）

> **この節は完了しています。** 記録として残しますが、再度の操作は不要です。移管ロック・WHOIS代行とも **ON** になっていることを画面で確認済み（2026-07-29）。

**サイトを繋ぐ前に、ドメインそのものを守る設定を先に済ませます。** ドメインを他人に奪われると、サイトもメールも丸ごと乗っ取られます。

### (1) 移管ロックを **ON** にする（最優先）✅ 完了

取得直後は **「移管ロック」が OFF** でした。**ON に切り替えます。**

- **移管ロックとは**: 「このドメインを他の業者へ引っ越しさせない」という鍵です。
- OFF のままだと、後述の **AuthCode を知った人が、あなたに無断で他社へドメインを移せてしまいます**。
- ON にしても、自動更新やサイト表示には**一切影響しません**。将来あなた自身が他社へ移したくなったら、その時だけ OFF に戻せば済みます。

### (2) AuthCode は「パスワードと同じ」扱いにする

同じ画面に **AuthCode**（記号を含んだランダムな文字列）が表示されています。これは**ドメインを他社へ移すための暗証番号**です。

- ⚠️ **先ほど送っていただいたスクリーンショットには、この AuthCode がそのまま写っていました。** 私（Claude）はこの値をリポジトリやメモに一切保存していませんが、**画面共有・メール添付・チャット投稿などで第三者の目に触れると危険**です。
- **対処**: まず上の (1) 移管ロックを ON にしてください。**ロックが ON なら、AuthCode を知られても勝手に移管されることはありません**（これで実害は防げます）。
- ConoHa の画面に AuthCode の**再発行（変更）**ボタンがある場合は、念のため再発行しておくとより安全です。見当たらなければロック ON だけで構いません。
- 今後スクリーンショットを共有するときは、**AuthCode の行を隠して**ください。

### (3) Whois代行を **ON** にする ✅ 完了

取得直後は **「設定中」** と表示されていましたが、**2026-07-29 に ON になっていることを確認済み**です。

- **Whois代行とは**: ドメイン登録者の住所・電話番号・メールアドレスを、業者の情報に置き換えて公開する仕組みです。これが効いていないと、**登録した連絡先が誰でも見られる状態でインターネットに公開されます**。
- 📌 **`.jp` ドメインの注意**: `.jp` は仕様上、**登録者の「組織名」は代行を使っても公開されます**。ただし今回は**株式会社パートナー名義**の想定なので、**会社名が出るのはむしろ事業サイトとして自然**であり、問題ありません。隠したいのは担当者の個人情報（住所・電話・メール）で、そこは代行が効きます。
- 📌 **ConoHa の画面に出る注意書きについて**: WHOIS代行の欄に「※契約種別、氏名、組織名、メールアドレスのいずれかを変更した場合は対象ドメインの移管(OUT)が60日間行えません」という表示があります。これは**登録者情報を変えた直後は他社へ引っ越せない**という意味で、**このサイトの運用には何の影響もありません**（他社へ移す予定が無いため）。

## 手順1：Vercel にドメインを登録する（✅ 2026-07-29 実施済み・約10分）

> **この節は実施済みです。** 以下は**実際に行った操作の記録**で、同じ作業を再度行う必要はありません。将来ドメインを追加・変更するときの参照用に残しています。

### 方針：`yingpin.jp` を正とし、`www.yingpin.jp` はそこへ転送

- **理由**: URLは**WeChatでのリンク共有・チラシ・口頭説明**で使われるため、短い方が伝え間違いが減る。また**利用規約・プライバシーポリシー・スタッフ手順書にも載る**ので、後から変えると差し替え箇所が増える
- ⚠️ **Vercel は逆（`www` を正とする）を "recommended" と表示するが、あえて外した。** Vercelの推奨は技術的にわずかに扱いやすいという理由で、このサイトの規模では差が出ない

### 操作の記録

1. Vercel にログインし、プロジェクト（`job-site-for-specified-skilled-workers`）を開く
2. **Settings** → **Domains**
3. 右上の **「Add Existing」** を押す
   - ⚠️ **中央の `Search any domain` 欄は「購入できるドメインを探す検索窓」で、ここからは追加できない。** 黒い **「Buy」** は新規購入（押すと二重購入になる）
4. **`yingpin.jp`** を入力
   - **`Redirect apex domains to www (recommended)` のチェックを外す** ⬅️ **ここが要点**
   - **`Connect to an environment` → `Production`** を選ぶ（= 本番。このサイトは Vercel の本番ブランチが `main` ではなく `claude/skilled-worker-job-site-mock-lk07i6` だが、**`Production` を選べば正しくそのブランチに繋がる**）
   - **Add Domain**
5. もう一度 **「Add Existing」** を押し、**`www.yingpin.jp`** を追加する
   - 🔴 **`Include apex and www variants (recommended)` のチェックを必ず外す。** 外さないと Vercel が `yingpin.jp` も一緒に追加しようとし、転送先も `yingpin.jp` のため **`A domain cannot redirect to itself.`（自分自身には転送できません）** というエラーになる
   - **`Redirect to Another Domain`** を選ぶ
   - 種類は **`308 Permanent Redirect`**（恒久的な方針なので一時転送の 307 ではなく 308）
   - 転送先に **`yingpin.jp`** を選ぶ
   - **Add Domain**
6. 一覧の各行の **`View DNS configuration`** を開くと、**DNS に設定すべき値**が表示される

### このプロジェクトで実際に指示された値

| ドメイン | Type | Name | Value |
|---|---|---|---|
| `yingpin.jp` | **A** | `@` | **`216.198.79.1`** |
| `www.yingpin.jp` | **CNAME** | `www` | **`e7a29a99ea1defe5.vercel-dns-017.com.`** |

> 🔴 **一般に案内されている `76.76.21.21` / `cname.vercel-dns.com` ではなかった。** 画面には「We're expanding our IP range. We recommend the records above.（IPレンジを拡張中です。上記のレコードを推奨します）」と出ており、**旧来の値も動くが推奨は上表**という状態。**推測で入力せず、必ず Vercel の画面のコピーボタンから貼り付けること。**
>
> 特に CNAME の値は**プロジェクト固有のランダムな文字列**で、`0`（ゼロ）と `O`（オー）、`1`（イチ）と `l`（エル）の区別が目視では危うい。**1文字違うと永久に繋がらない。**

## 手順2：ConoHa で DNS を設定する（✅ 2026-07-29 実施済み・約10分）

> **この節は実施済みです。** 以下は**実際に行った操作の記録**です。

### 2-0. 先に「ネームサーバー設定」を確認する（重要）

ConoHa の `ドメイン → yingpin.jp` の画面を下にスクロールすると **「ネームサーバー設定」** という折りたたまれた項目があります。**ここの設定次第で次にやることが変わる**ため、先に開いて確認します。

| 表示されている内容 | 意味 | 次にやること |
|---|---|---|
| `ns-a1.conoha.io` など **conoha** を含む名前 | ConoHa の DNS を使っている（正常） | **↓ 2-1 へ進む** |
| **空欄** または「未設定」 | DNS がどこにも向いていない＝**このままでは絶対にサイトが表示されない** | Claude に連絡（ConoHa の DNS に向ける設定を案内します） |
| 上記以外 | 別のサービスを向いている | Claude に連絡 |

✅ **実際の結果**: タブが **`ConoHa(標準)`** で、`ns-a1.conoha.io` / `ns-a2.conoha.io` / `ns-a3.conoha.io` の3件。**正常**だったのでそのまま 2-1 へ進んだ。

> ⚠️ 画面の **「サーバー利用: 未設定」** は問題ありません。これは「ConoHa のレンタルサーバーを使っていない」という意味で、**サイト本体は Vercel にあるので正しい状態**です。ConoHa からレンタルサーバーを契約する必要はありません。

### 2-1. 🔴 DNS リストにドメインを追加する（見落としやすい）

**ネームサーバーが `ConoHa(標準)` を向いていても、左メニュー「DNS」のドメインリストに `yingpin.jp` が自動では入らない。** 実際、取得直後のリストには既存の2ドメインしか無かった。

1. ConoHa の**左メニューの「DNS」**（地球儀アイコン）を開く
2. リストに **`yingpin.jp`** が**無ければ**、右上の青い **「＋ ドメイン」** を押して `yingpin.jp` を追加する
3. 追加すると `yingpin.jp` の行が増え、開くと **NS レコード3件だけ**が入った状態になっている

### 2-2. レコードを2件追加する

1. リストの **`yingpin.jp`** の `>` を押して開く
2. 表の右上の **鉛筆アイコン ✏️** を押して編集モードにする
3. **「＋」** で行を追加し、手順1で Vercel が表示した値を入力する

   | | タイプ | 名称 | TTL | 値 |
   |---|---|---|---|---|
   | 1件目（サイト本体） | **A** | **`@`** | 3600 | Vercel が表示した IP |
   | 2件目（www 付き） | **CNAME** | **`www`** | 3600 | Vercel が表示した CNAME 値 |

4. **「保存」を押す**（押し忘れが最も多い失敗）

✅ **実際に入力した値**:

| タイプ | 名称 | TTL | 値 |
|---|---|---|---|
| A(通常) | `@` | 3600 | `216.198.79.1` |
| CNAME | `www` | 3600 | `e7a29a99ea1defe5.vercel-dns-017.com` |

> 💡 **CNAME の末尾のドット（`.`）**: Vercel の表示は `...com.` とドット付きだが、**ドットごと貼り付けて保存すると ConoHa 側が自動で外して保存する**（保存後の表示はドット無し）。これで正常に機能した。エラーになる場合はドットを外して再保存する。

> 🔴 **既にある NS 3件（`ns-a1〜a3.conoha.io`）は絶対に消さないこと。** 「このドメインの住所録は ConoHa が管理している」という土台の宣言で、消すとドメイン全体が機能しなくなる。**追加だけを行う。**

### 2-2.（参考）別のやり方：ネームサーバーごと Vercel に預ける

ConoHa の「ネームサーバー設定」に `ns1.vercel-dns.com` / `ns2.vercel-dns.com` を入れると、DNS の管理まるごとを Vercel 側で行えます。レコードの入力ミスが起きにくいという利点があります。

**ただし今回は 2-1 の方法（ConoHa の DNS を使う）を推奨します。** 理由は、ネームサーバーの変更の方が反映に時間がかかり、失敗したときに「サイトもメールも全部止まる」という影響範囲になるためです。**すでにこの方法で進めてしまった場合も問題ないので、その旨を Claude に伝えてください**（以降の入力先が Vercel の画面に変わるだけです）。

## 手順3：反映を待って確認する（最大48時間・通常は数分〜数時間）

1. Vercel の **Settings → Domains** を開きます。
2. 各行の **「Refresh」** を押します。**「Valid Configuration」（設定OK）** に変われば完了です。
   - しばらくは赤い表示が出ますが、**すぐには焦らないでください**。DNS の反映待ちです。
   - 数時間経っても赤いままなら、その画面のスクリーンショットを Claude に送ってください。
3. ブラウザで `https://yingpin.jp` を開き、サイトが表示され、**アドレス欄に鍵マーク**が出ることを確認します。
   - HTTPS の証明書は **Vercel が自動で取得**します。あなたの操作は不要です。

### ⚠️ `Failed To Generate Cert` と出ても、たいていは故障ではない

DNS 保存の直後、`yingpin.jp` の行にこう出ることがある:

```
Failed To Generate Cert
We could not generate a cert for yingpin.jp because the required http-01 challenge failed.
During secondary validation: no valid A records found for yingpin.jp;
no valid AAAA records found for yingpin.jp
```

**意味**: Vercel が HTTPS の証明書を取ろうとしたが、その時点では A レコードがまだ Vercel 側から見えなかった、というだけ。**設定の誤りとは限らない。**

**背景**: DNS には「答えが無かった」という結果も一定時間キャッシュされる性質がある。ConoHa の DNS リストにドメインを追加する前は、`yingpin.jp` を引いても答えが返らない状態だったため、その「無い」がしばらく残る。TTL は 3600（1時間）。

**対処**: **数分〜1時間ほど待ってから `Refresh` を押し直す。** 証明書の取得は Vercel が自動で再試行するので、こちらの操作は Refresh だけでよい。

**切り分けの目安**: `www.yingpin.jp` が先に `Valid Configuration` になっているなら、**ネームサーバーもゾーンも正しく機能している証拠**。apex（`yingpin.jp`）だけが遅れているだけなので、待てば追いつく。

✅ **実際の経過（2026-07-29）**: CNAME 保存の直後、`www.yingpin.jp` は `Valid Configuration`、`yingpin.jp` は `Failed To Generate Cert` だった。しかし外部から DNS を引くと **`yingpin.jp → 216.198.79.1`（指定どおり）／`www.yingpin.jp → 216.198.79.65, 64.29.17.65`（Vercelのサーバー）** と**すでに正しく解決できていた**＝反映は進んでおり、Vercel 側の確認タイミングの問題だった。

> 💡 **確認したいときは Claude に頼めます。** Claude の実行環境から DNS を引いて、「世界から見て今どう見えているか」を客観的に確認できます（ブラウザのキャッシュに影響されない判定）。

> ✅ **緑になったら Claude に連絡してください。** ここから先の仕上げ作業（手順5）はこちらで行います。

## 手順4：通知メールの送信元を `@yingpin.jp` にする（約15分＋反映待ち）

### なぜ必要か

現在、**新規登録・新規応募のスタッフ通知メール**は Resend というサービスの**テスト用アドレス（`onboarding@resend.dev`）**から送られています。この状態では：

- 🔴 **オーナー（`yazawa-y@partner-japan.biz`）宛にしか届きません。** 他のスタッフを宛先に追加しても届きません。
- 迷惑メールフォルダに入りやすくなります。

自社ドメインを認証すると、**スタッフ複数名に通知が届く**ようになります。

### 手順

1. Resend（`https://resend.com`）にログインし、**Domains → Add Domain** を開きます。
2. ドメイン名は **`yingpin.jp`** を入力します。
   - 💡 Resend が「サブドメインを推奨」と案内する場合は、`send.yingpin.jp` のような形でも構いません（**サイト本体の表示には一切影響しません**）。迷ったら `yingpin.jp` のままで進めてください。
3. Resend が **DNS に追加すべきレコード（TXT が2〜3件、MX が1件）** を表示します。これが **SPF / DKIM** と呼ばれる「このメールは本物です」という証明用の設定です。
4. **手順2-1 と同じ ConoHa の DNS 画面**で、表示されたレコードを1件ずつ追加して**保存**します。
   - ⚠️ **DKIM の値は非常に長い文字列**（数百文字）です。**手打ちせず、必ずコピー＆ペースト**してください。前後に余計な空白や改行が入らないよう注意します。
   - ⚠️ Resend の画面に出ている **Name（名前）欄をそのまま**使ってください。`resend._domainkey` のような値です。
5. Resend の画面に戻り **Verify**（確認）を押します。緑の **Verified** になれば成功です（反映まで数分〜数時間）。
6. **Vercel の Settings → Environment Variables** で、次の環境変数を設定（または修正）します。

   | キー | 値 |
   |---|---|
   | `NOTIFY_FROM_EMAIL` | `樱聘 YingPin <no-reply@yingpin.jp>` |
   | `STAFF_NOTIFY_EMAILS` | 通知を受け取るスタッフのアドレス（カンマ区切りで複数可） |

7. 保存後、**再デプロイ**が必要です（環境変数は再デプロイで反映されます）。**Claude に連絡いただければ、この再デプロイまで含めて案内します。**
8. テスト登録を1件行い、**設定した全員に通知メールが届く**ことを確認します。

- [x] **旧 `.vercel.app` アドレスの扱い** — **そのまま残す**（下記の理由）

### HSTS の段階導入（重要・引き上げ予定あり）

**HSTS** は「このサイトには今後必ず HTTPS で来なさい」とブラウザに覚えさせる設定です。覚えている間、ブラウザは `http://` を自動で HTTPS に書き換え、証明書の警告を「無視して進む」こともできなくなります（通信の盗聴・改ざんを防ぐ）。

⚠️ **撤回が効きにくい**のが要点です。設定を消しても、**すでに覚えたブラウザは期間が切れるまで HTTPS を要求し続けます。** そのため一気に入れず段階を踏みます。

| 段 | 時期 | 設定 | 状態 |
|---|---|---|---|
| **第1段** | 2026-07-29 | `max-age=86400`（**1日**）のみ | ✅ **実施済み** |
| **第2段** | 1週間ほど様子を見て、かつ**手順4（Resend）でサブドメイン構成が確定した後** | `max-age=31536000`（1年）＋ `includeSubDomains` | 🔜 未実施 |
| **第3段** | 当面**見送り** | `preload` の付与と hstspreload.org への登録 | ⏸ 保留 |

- **第1段を1日にした理由**: 万一何かが動かなくなっても、**24時間で自然に元へ戻る**ため。
- **第1段で `includeSubDomains` を付けない理由**: `yingpin.jp` の**サブドメインを今後増やす予定**があるため（手順4で通知メール用に `send.yingpin.jp` 等を作る可能性）。HTTPS に対応しないサブドメインを作ってしまうと、そこへ到達できなくなります。
- **第3段（preload）を見送る理由**: 登録すると**解除に数か月かかります**。運用が安定してから判断します。

> 🔖 **次のセッションのClaudeへ**: 第2段の引き上げは `app/next.config.ts` の `HSTS_MAX_AGE_SECONDS` と `Strict-Transport-Security` の行を変えるだけ。**手順4（Resend）の完了を待つこと。**

### 旧 `.vercel.app` を残す理由

`https://job-site-for-specified-skilled-work.vercel.app` は**そのまま生かしておきます**。

## よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| Vercel が「Invalid Configuration」のまま | ①DNS の反映待ち（最大48h・まず待つ）②ConoHa で**保存を押していない** ③値の打ち間違い（特に IP の数字）④名称欄に `yingpin.jp` とフルで書いてしまった（`@` が正解） |
| **`Failed To Generate Cert`** と赤く出る | **たいていは反映待ち。** 手順3の該当節を参照。数分〜1時間待って `Refresh` を押し直す |
| **`A domain cannot redirect to itself.`** | `www.yingpin.jp` を追加するとき **`Include apex and www variants` のチェックが入っている**のが原因。外す（手順1-5） |
| **ConoHa の DNS 一覧に `yingpin.jp` が無い** | **ネームサーバーが ConoHa 標準でも、DNS リストには自動で入らない。** 右上の「＋ドメイン」で追加する（手順2-1） |
| Vercel の Domains 画面に追加の入口が見当たらない | 右上の **「Add Existing」**。中央の `Search any domain` は購入検索窓、黒い **「Buy」** は新規購入なので押さない |
| `www.yingpin.jp` だけ見えない | CNAME レコードの名称が `www` になっているか、値が Vercel の指示どおりか確認 |
| サイトは見えるが鍵マークが出ない | 証明書の発行待ち（通常は数分）。1時間以上続くなら Claude に連絡 |
| メールが Verified にならない | DKIM の値のコピー漏れ・改行混入が最多。値を消して貼り直す |
| 「レンタルサーバーも契約が必要では？」 | **不要です。** サイト本体は Vercel、データは Supabase にあります |

## 用語ミニ辞典（このガイド用）

| 用語 | 意味 |
|---|---|
| A レコード | ドメイン名を「サーバーの番地（IPアドレス）」に結びつける設定 |
| CNAME レコード | ドメイン名を「別のドメイン名」に転送する設定。`www` に使う |
| TXT レコード | ドメインに自由な文字列をぶら下げる設定。メールの証明（SPF/DKIM）に使う |
| MX レコード | そのドメイン宛のメールをどこで受け取るかの設定 |
| ネームサーバー | 「このドメインの DNS 設定は、この会社が管理しています」という宣言 |
| AuthCode | ドメインを他社へ引っ越すための暗証番号。**パスワード同然の秘密情報** |
| 移管ロック | 無断でドメインを他社へ移されないようにする鍵 |
| HSTS | 一度 HTTPS で接続したブラウザに、以後必ず HTTPS を使わせる設定 |

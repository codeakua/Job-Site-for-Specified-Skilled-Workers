> **このガイドの目的**: 2026-07-29 に ConoHa で取得した **`yingpin.jp`** を、サイトを配信している **Vercel** に繋ぎ、通知メールの送信元も自社ドメインにする。

> **前提**: ドメインの購入は完了済み（→ 購入前の検討は `domain-setup-guide.md`。**本ガイドはその続き**）。

> **所要時間**: 画面操作は合計30〜40分。ただし **DNS の反映に最大48時間**かかるため、稼働日 **8/8** から逆算して早めに進めること。

## 🔴 手順0：今すぐやる安全確認（3つ・5分）

**サイトを繋ぐ前に、ドメインそのものを守る設定を先に済ませます。** ドメインを他人に奪われると、サイトもメールも丸ごと乗っ取られます。

### (1) 移管ロックを **ON** にする（最優先）

ConoHa の画面（`ドメイン → yingpin.jp`）で **「移管ロック」が OFF** になっています。**ON に切り替えてください。**

- **移管ロックとは**: 「このドメインを他の業者へ引っ越しさせない」という鍵です。
- OFF のままだと、後述の **AuthCode を知った人が、あなたに無断で他社へドメインを移せてしまいます**。
- ON にしても、自動更新やサイト表示には**一切影響しません**。将来あなた自身が他社へ移したくなったら、その時だけ OFF に戻せば済みます。

### (2) AuthCode は「パスワードと同じ」扱いにする

同じ画面に **AuthCode**（記号を含んだランダムな文字列）が表示されています。これは**ドメインを他社へ移すための暗証番号**です。

- ⚠️ **先ほど送っていただいたスクリーンショットには、この AuthCode がそのまま写っていました。** 私（Claude）はこの値をリポジトリやメモに一切保存していませんが、**画面共有・メール添付・チャット投稿などで第三者の目に触れると危険**です。
- **対処**: まず上の (1) 移管ロックを ON にしてください。**ロックが ON なら、AuthCode を知られても勝手に移管されることはありません**（これで実害は防げます）。
- ConoHa の画面に AuthCode の**再発行（変更）**ボタンがある場合は、念のため再発行しておくとより安全です。見当たらなければロック ON だけで構いません。
- 今後スクリーンショットを共有するときは、**AuthCode の行を隠して**ください。

### (3) Whois代行が「設定済み」になったか、あとで確認する

画面では **「設定中」** と表示されています。これは手続き中の状態なので、**1日ほど経ってから同じ画面を開き、「設定済み」に変わっているか確認**してください。

- **Whois代行とは**: ドメイン登録者の住所・電話番号・メールアドレスを、業者の情報に置き換えて公開する仕組みです。これが効いていないと、**登録した連絡先が誰でも見られる状態でインターネットに公開されます**。
- 📌 **`.jp` ドメインの注意**: `.jp` は仕様上、**登録者の「組織名」は代行を使っても公開されます**。ただし今回は**株式会社パートナー名義**の想定なので、**会社名が出るのはむしろ事業サイトとして自然**であり、問題ありません。隠したいのは担当者の個人情報（住所・電話・メール）で、そこは代行が効きます。
- 何日経っても「設定中」のままなら、ConoHa のサポートへ問い合わせてください。

## 手順1：Vercel にドメインを登録する（あなたの操作・約5分）

1. Vercel にログインし、このサイトのプロジェクトを開きます。
   ```
   https://vercel.com/dashboard
   ```
2. **Settings**（設定）→ **Domains**（ドメイン）を開きます。
3. 入力欄に **`yingpin.jp`** と入力して **Add**（追加）を押します。
4. 「`www.yingpin.jp` も一緒に追加しますか？」という趣旨の選択肢が出ます。
   **おすすめは「`yingpin.jp` を正とし、`www.yingpin.jp` はそこへ転送（Redirect）」** です。
   - 理由: 短いアドレスの方が中国のSNSやWeChatで共有しやすく、口頭でも伝えやすいためです。
   - どちらを選んでも機能に差はありません。迷ったら上記のとおりにしてください。
5. すると Vercel が **「DNS にこの値を設定してください」という指示**を画面に表示します。
   典型的にはこの2つです（**★ただし正解は必ず画面に出ている値です**）:

   | 種類 | 名前 | 値（例） |
   |---|---|---|
   | **A** | `@`（＝ `yingpin.jp` 本体） | `76.76.21.21` |
   | **CNAME** | `www` | `cname.vercel-dns.com` |

> 🔴 **ここが一番大事**: 上の表の値は**一般的な例**です。**プロジェクトによって違う値が指示されることがあります**（`216.198.79.1` や `cname.vercel-dns-0.com` など）。
> **必ず Vercel の画面に表示された値をそのまま使ってください。** この画面のスクリーンショットを Claude に送っていただければ、次の手順の入力値を確定してお伝えします。

## 手順2：ConoHa で DNS を設定する（あなたの操作・約10分）

### 2-0. 先に「ネームサーバー設定」を確認する（重要）

ConoHa の `ドメイン → yingpin.jp` の画面を下にスクロールすると **「ネームサーバー設定」** という折りたたまれた項目があります。**ここを開いて、中身のスクリーンショットを Claude に送ってください。**

なぜ先に確認するかというと、**ここの設定次第で次にやることが変わる**からです。

| 表示されている内容 | 意味 | 次にやること |
|---|---|---|
| `ns-a1.conoha.io` など **conoha** を含む名前 | ConoHa の DNS を使っている（正常） | **↓ 2-1 へ進む** |
| **空欄** または「未設定」 | DNS がどこにも向いていない＝**このままでは絶対にサイトが表示されない** | Claude に連絡（ConoHa の DNS に向ける設定を案内します） |
| 上記以外 | 別のサービスを向いている | Claude に連絡 |

> ⚠️ 画面の **「サーバー利用: 未設定」** は問題ありません。これは「ConoHa のレンタルサーバーを使っていない」という意味で、**サイト本体は Vercel にあるので正しい状態**です。ConoHa からレンタルサーバーを契約する必要はありません。

### 2-1. DNS にレコードを2つ追加する

1. ConoHa の**左メニューの「DNS」**を開きます。
2. 一覧から **`yingpin.jp`** を選びます。
   - ⚠️ **一覧に `yingpin.jp` が無い場合**は 2-0 の確認結果に問題があります。Claude に連絡してください。
3. **「＋」ボタン**を押してレコードを1行追加し、手順1で Vercel が表示した値を入力します。

   **1つ目（サイト本体）**

   | 欄 | 入れる値 |
   |---|---|
   | タイプ | **A** |
   | 名称 | **`@`**（空欄でも可。「ドメイン名そのもの」という意味） |
   | TTL | 既定値のまま（3600 など） |
   | 値 | **Vercel が表示した IP アドレス**（例 `76.76.21.21`） |

   **2つ目（www 付きのアドレス）**

   | 欄 | 入れる値 |
   |---|---|
   | タイプ | **CNAME** |
   | 名称 | **`www`** |
   | TTL | 既定値のまま |
   | 値 | **Vercel が表示した値**（例 `cname.vercel-dns.com.`） |

4. **「保存」を押します。**（押し忘れが最も多い失敗です）

> 💡 **CNAME の値の末尾のドット（`.`）について**: ConoHa の画面では末尾にドットを付ける必要がある場合があります。画面の入力例に合わせてください。**判断がつかなければ入力途中のスクリーンショットを送ってください。**

> ⚠️ **既にある他のレコードは消さないでください。** 追加だけを行います。

### 2-2.（参考）別のやり方：ネームサーバーごと Vercel に預ける

ConoHa の「ネームサーバー設定」に `ns1.vercel-dns.com` / `ns2.vercel-dns.com` を入れると、DNS の管理まるごとを Vercel 側で行えます。レコードの入力ミスが起きにくいという利点があります。

**ただし今回は 2-1 の方法（ConoHa の DNS を使う）を推奨します。** 理由は、ネームサーバーの変更の方が反映に時間がかかり、失敗したときに「サイトもメールも全部止まる」という影響範囲になるためです。**すでにこの方法で進めてしまった場合も問題ないので、その旨を Claude に伝えてください**（以降の入力先が Vercel の画面に変わるだけです）。

## 手順3：反映を待って確認する（最大48時間・通常は数分〜数時間）

1. Vercel の **Settings → Domains** を開きます。
2. `yingpin.jp` の欄が **「Valid Configuration」（設定OK）** の**緑色**の表示に変われば完了です。
   - しばらくは「Invalid Configuration」と赤く出ますが、**すぐには焦らないでください**。DNS の反映待ちです。
   - 数時間経っても赤いままなら、その画面のスクリーンショットを Claude に送ってください。
3. ブラウザで `https://yingpin.jp` を開き、サイトが表示され、**アドレス欄に鍵マーク**が出ることを確認します。
   - HTTPS の証明書は **Vercel が自動で取得**します。あなたの操作は不要です。

> ✅ **確認できたら Claude に連絡してください。** ここから先の仕上げ作業（手順5）はこちらで行います。

## 手順4：通知メールの送信元を `@yingpin.jp` にする（約15分＋反映待ち）

### なぜ必要か

現在、**新規登録・新規応募のスタッフ通知メール**は Resend というサービスの**テスト用アドレス（`onboarding@resend.dev`）**から送られています。この状態では：

- 🔴 **オーナー（`yazawa-y@partner-japan.biz`）宛にしか届きません。** 他のスタッフを宛先に追加しても届きません。
- 迷惑メールフォルダに入りやすくなります。

自社ドメインを認証すると、**スタッフ複数名に通知が届く**ようになります。

### 手順

1. Resend（`https://resend.com`）にログインし、**Domains → Add Domain** を開きます。
2. ドメイン名は **`yingpin.jp`** を入力します。
   - 💡 Resend が「サブドメインを推奨」と案内する場合は、`send.yingpin.jp` のような形でも構いません（**サイト本体の表示には一切影響しません**）。迷ったら `yingpin.jp` のままで進めてください。
3. Resend が **DNS に追加すべきレコード（TXT が2〜3件、MX が1件）** を表示します。これが **SPF / DKIM** と呼ばれる「このメールは本物です」という証明用の設定です。
4. **手順2-1 と同じ ConoHa の DNS 画面**で、表示されたレコードを1件ずつ追加して**保存**します。
   - ⚠️ **DKIM の値は非常に長い文字列**（数百文字）です。**手打ちせず、必ずコピー＆ペースト**してください。前後に余計な空白や改行が入らないよう注意します。
   - ⚠️ Resend の画面に出ている **Name（名前）欄をそのまま**使ってください。`resend._domainkey` のような値です。
5. Resend の画面に戻り **Verify**（確認）を押します。緑の **Verified** になれば成功です（反映まで数分〜数時間）。
6. **Vercel の Settings → Environment Variables** で、次の環境変数を設定（または修正）します。

   | キー | 値 |
   |---|---|
   | `NOTIFY_FROM_EMAIL` | `樱聘 YingPin <no-reply@yingpin.jp>` |
   | `STAFF_NOTIFY_EMAILS` | 通知を受け取るスタッフのアドレス（カンマ区切りで複数可） |

7. 保存後、**再デプロイ**が必要です（環境変数は再デプロイで反映されます）。**Claude に連絡いただければ、この再デプロイまで含めて案内します。**
8. テスト登録を1件行い、**設定した全員に通知メールが届く**ことを確認します。

## 🔴 手順6：中国からの接続確認（これが本番の検証）

**このドメインを取った一番の目的は「中国から見えるようにすること」です。**

`.vercel.app` は中国本土から接続できない／不安定と広く報告されており、独自ドメインはその回避のための必須作業でした。ただし——

> ⚠️ **独自ドメインにすれば必ず見えるようになる、という保証はありません。** 中国からの接続可否は日本側からは確認できません。

**必ず、中国在住の知人・取引先に実際にアクセスしてもらってください。**

- 確認してもらう URL: `https://yingpin.jp`
- **スマホの携帯回線（4G/5G）と Wi-Fi の両方**で試してもらう（回線によって結果が違うことがあります）
- 見えた／見えない だけでなく、**「表示に何秒かかったか」**も聞いてください（極端に遅い場合は対策が要ります）

これが唯一の確実な検証手段です。**稼働日 8/8 より前に必ず済ませてください。**

## よくあるつまずき

| 症状 | 原因と対処 |
|---|---|
| Vercel が「Invalid Configuration」のまま | ①DNS の反映待ち（最大48h・まず待つ）②ConoHa で**保存を押していない** ③値の打ち間違い（特に IP の数字）④名称欄に `yingpin.jp` とフルで書いてしまった（`@` か空欄が正解） |
| `www.yingpin.jp` だけ見えない | CNAME レコードの名称が `www` になっているか、値が Vercel の指示どおりか確認 |
| サイトは見えるが鍵マークが出ない | 証明書の発行待ち（通常は数分）。1時間以上続くなら Claude に連絡 |
| ConoHa の DNS 一覧に `yingpin.jp` が無い | ネームサーバーが ConoHa を向いていない可能性。手順2-0 を確認 |
| メールが Verified にならない | DKIM の値のコピー漏れ・改行混入が最多。値を消して貼り直す |
| 「レンタルサーバーも契約が必要では？」 | **不要です。** サイト本体は Vercel、データは Supabase にあります |

## 用語ミニ辞典（このガイド用）

| 用語 | 意味 |
|---|---|
| A レコード | ドメイン名を「サーバーの番地（IPアドレス）」に結びつける設定 |
| CNAME レコード | ドメイン名を「別のドメイン名」に転送する設定。`www` に使う |
| TXT レコード | ドメインに自由な文字列をぶら下げる設定。メールの証明（SPF/DKIM）に使う |
| MX レコード | そのドメイン宛のメールをどこで受け取るかの設定 |
| ネームサーバー | 「このドメインの DNS 設定は、この会社が管理しています」という宣言 |
| AuthCode | ドメインを他社へ引っ越すための暗証番号。**パスワード同然の秘密情報** |
| 移管ロック | 無断でドメインを他社へ移されないようにする鍵 |
| HSTS | 一度 HTTPS で接続したブラウザに、以後必ず HTTPS を使わせる設定 |

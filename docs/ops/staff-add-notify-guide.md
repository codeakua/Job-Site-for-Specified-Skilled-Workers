# 管理者を追加し、通知メールの宛先を決める手順（張海岩さん・祝北辰さん）

> **この手順でできること**
> - 張海岩さん・祝北辰さんが**管理画面 `/admin`**（求人管理・会員管理・応募管理）を開けるようになる
> - **張海岩さんだけ**が、応募・新規登録があったときの**通知メール**を受け取れるようになる（祝北辰さんには送らない）
>
> **所要時間**: 管理画面の追加＝お一人10分／通知メールの追加＝10分（ただし前提作業あり・第6章）
> **やる人**: オーナー（Supabase と Vercel にログインできる方）
> 途中で分からなくなったら、**その画面をそのままClaudeに見せてください。**

---

## 1. いちばん大事なこと（最初にお読みください）

### ① 「管理画面を使える」と「通知メールが届く」は、**まったく別の設定**です

| やりたいこと | どこで設定するか | 今回の対象 |
|---|---|---|
| 管理画面 `/admin` を開けるようにする | **Supabase** の職員名簿（`staff_users`） | 張海岩さん・祝北辰さん **両方** |
| 応募・登録の通知メールを受け取る | **Vercel** の設定 `STAFF_NOTIFY_EMAILS` | 張海岩さん **だけ** |

**片方だけを設定してももう片方には影響しません。** ですので、ご要望のとおり「二人とも管理画面は使えるが、メールは張海岩さんにだけ届く」という形にできます。祝北辰さんについては、**メール側で何もしなければそれで完了**です（第7章）。

### ② 職員名簿に書くメールアドレスは、ただのメモです

第4章で職員名簿に登録するとき、氏名とメールアドレスを書く欄があります。この**メールアドレスは「誰を登録したか後で分かるようにする」ためのメモ**で、ここに書いても通知メールは1通も届きません。**通知メールの宛先は第6章の作業でしか決まりません。**

（ログインも同様で、メールアドレスではログインできません。ログインは**電話番号とパスワード**で行います。）

### ③ 通知メールには、求職者の個人情報がそのまま載ります

通知メールの本文には、応募・登録した方の**氏名・電話番号・WeChat ID・メールアドレス・在住国**が記載されます。**宛先を1文字間違えると、他人に個人情報を送ってしまいます。** 第6章のアドレスは、必ずご本人に確認したうえで入力してください。

> 💡 できれば、通知の宛先は**個人のプライベートなアドレスより会社が管理するアドレス**のほうが安全です（退職時にオーナー側で止められるため）。今回は張海岩さんのご希望のアドレスで進めて構いませんが、社用アドレスをお持ちなら、そちらを推奨します。

### ④ 🔴 いただいたアドレスの確認をお願いします

張海岩さんのアドレスとしていただいた **`zhanghongxia790513@icloud.com`** は、`@` の前が **zhanghongxia**（張紅霞）と読める並びで、**お名前の張海岩（zhang haiyan）とは一致しません。**

古くから使っているアドレスやご家族のアドレスであれば、そのままで問題ありません。ただ、③のとおり間違えると個人情報が他人に届いてしまうため、**「このアドレスで合っていますか」とご本人に一度だけ確認**してください。確認が取れたら、そのまま第6章に進んで構いません。

## 3. 手順1: お二人に会員登録してもらう

張海岩さん・祝北辰さんそれぞれに、次のURLを送って会員登録してもらいます。

```
https://yingpin.jp/register
```

伝えることは3つです。

1. **国番号と電話番号**を入力する（日本の番号なら `+81`、中国の番号なら `+86`）
2. **パスワードは8文字以上**。管理画面のログインに使うので必ず控えておく
3. 登録が終わったら、**入力した国番号と電話番号を、入力したとおりの表記でオーナーに伝える**（先頭に `0` を付けたかどうかも含めて）

> **なぜご本人に登録してもらうのか**: パスワードは暗号化されて保存されるため、オーナーでも中身を見ることはできません。ご本人が決めるのが最も安全で確実です。
>
> **この時点ではまだ「会員」です。** 管理画面はまだ開けません。第4章で職員名簿に追加すると開けるようになります。

## 4. 手順2・3: UIDを調べて、職員名簿に追加する

### UIDを調べる

1. Supabaseにログインし、プロジェクト `jdiybvtytrdkuxsiddic` を開く
2. 左メニューの **Authentication** → **Users**
3. **Email列に、その方の電話番号の数字が入っている行**を探す
4. その行の **UID をコピー**する

> ⛔ **「作成日時がいちばん新しい行」で選んではいけません。** 一般の求職者も同じ一覧に並びます。お二人の登録直後に別の求職者が登録すると、いちばん新しい行は**その求職者**になります。気づかずに進めると、**赤の他人に全会員の個人情報を見せてしまいます。**

**Email列の読み方**: `p` ＋ 国番号 ＋ 電話番号 ＋ `@phone.yingpin.app` の形で、**ご本人が入力したとおりの数字**が並びます。

| 国番号 | 本人が入力した電話番号 | Email列の表示 |
|---|---|---|
| +81 | 90-1234-5678 | `p819012345678@phone.yingpin.app` |
| +81 | 090-1234-5678 | `p8109012345678@phone.yingpin.app` |
| +86 | 138-0013-8000 | `p8613800138000@phone.yingpin.app` |

判別できないときは、**推測せずご本人にもう一度確認**してください。

### 職員名簿に追加する

左メニューの **SQL Editor** → **New query** に下のSQLを貼り付け、**UIDの2か所を書き換えて**から **Run** を押します（氏名とメールアドレスは記入済みです）。

```sql
insert into staff_users (id, email, name)
values
  ('ここに張海岩さんのUIDを貼る', 'zhanghongxia790513@icloud.com', '張 海岩'),
  ('ここに祝北辰さんのUIDを貼る', 'syuku_82@icloud.com',           '祝 北辰');
```

> **シングルクォート `'` は消さないでください。** 書き換えるのは `'` と `'` の**内側だけ**です。
>
> ここに書くメールアドレスは**メモ**です（第1章②）。通知メールはこれでは届きません。

## 5. 手順4: 登録できたか確認する

`Success. No rows returned` と出れば実行できています。**そのうえで必ず、意図した人が登録されたかを確認してください。** SQL Editorに次を貼り付けて Run します。

```sql
select s.id   as "UID",
       s.name as "氏名",
       u.email as "ログイン用の内部アドレス（電話番号）",
       s.created_at as "登録日時"
from staff_users s
join auth.users u on u.id = s.id
order by s.created_at;
```

**張海岩さん・祝北辰さんの行の「ログイン用の内部アドレス」に、それぞれご本人の電話番号の数字が入っていること**を目で確かめてください。違う番号になっていたら**別人に権限を与えています。** すぐに次のSQLで解除し、第4章からやり直してください。

```sql
delete from staff_users where id = 'ここに解除する人のUID';
```

最後に、お二人に `https://yingpin.jp/admin` を開いてもらいます。登録時の電話番号とパスワードでログインしてもらってください。管理画面が表示されれば成功です。

## 6. 手順5: 張海岩さんに通知メールを届ける

### 🔴 その前に必ず: 先に「宿題A（Resendのドメイン認証）」を終わらせてください

**この作業を先にやらないと、通知メールが張海岩さんに届かないだけでなく、いま届いているオーナー宛のメールまで一緒に止まる可能性がありました。**

いまの送信元は Resend というメール送信サービスの**テスト用アドレス（`onboarding@resend.dev`）**です。テスト用のままだと、Resendは**Resendアカウント所有者のアドレス宛以外を拒否します。** 張海岩さんのiCloudアドレスは拒否されます。

手順は `docs/ops/domain-conoha-vercel-guide.md` の「手順4」、期限は宿題一覧（`docs/ops/owner-checklist-2026-08-08.md` の **A**）にあるとおり **8/5** です。DNSの反映に最大48時間かかるため、**先にこちらを始めてください。**

> 🛡 **今回あわせて直したこと**: これまでは全員分を1通にまとめて送っていたため、**宛先が1つでも拒否されると全員に届かなくなる**作りでした。**宛先ごとに1通ずつ送る**ように変更したので、仮に張海岩さんのアドレスが拒否されても、**オーナー宛の通知は今までどおり届きます。** それでも張海岩さんに届かないことに変わりはないので、ドメイン認証は必要です。

### 設定のしかた

1. Vercel（`https://vercel.com`）にログインし、このプロジェクトを開く
2. **Settings** → **Environment Variables**（環境変数）
3. **`STAFF_NOTIFY_EMAILS`** の行を探し、右端の「…」→ **Edit**
4. 値の**末尾にカンマ（`,`）を打って、張海岩さんのアドレスを続けて書く**

```
yazawa-y@partner-japan.biz,zhanghongxia790513@icloud.com
```

> - **カンマの前後に空白があっても構いません**（プログラム側で取り除きます）。
> - **祝北辰さんのアドレスは書かないでください。** 書かなければ通知は届きません。それがご要望どおりの状態です。
> - 環境（Production / Preview / Development）は、**もとの `STAFF_NOTIFY_EMAILS` と同じところにチェックが入っていること**を確認してください。

5. **Save** を押す
6. 🔴 **再デプロイする。** 環境変数は**保存しただけでは本番サイトに反映されません。** **Deployments** タブを開き、いちばん上（最新）の行の「…」→ **Redeploy** → **Redeploy** を押します（2〜3分で終わります）。

### 設定できたか確認する

再デプロイが終わったら、`https://yingpin.jp/admin`（ダッシュボード）を開き、いちばん下の **「システム状態」** を見てください。

**「通知メールの宛先」** の行に、**いま実際に宛先になっているアドレスがそのまま表示されます。**

- ✅ 張海岩さんのアドレスが並んでいる／祝北辰さんのアドレスは無い → 意図どおりです
- ⚠️ 「送信元がResendのテスト用アドレスのため…」という警告が出ている → **宿題Aがまだ終わっていません。** この状態では張海岩さんには届きません
- ⚠️ 変更したのに表示が変わらない → **手順6の再デプロイをしていません**

> この画面は**スタッフだけが見られる**ページです（管理画面の中なので、求職者には表示されません）。

## 7. 祝北辰さんについて（何もしないでください）

祝北辰さんは、**第4章までで完了**です。第6章の作業をしなければ、通知メールは届きません。

- 管理画面 `/admin` は使えます（求人・会員・応募のすべてを見られます）
- 応募や新規登録があっても、メールは届きません。管理画面を開いて確認する形になります
- あとから通知が必要になったら、第6章と同じ手順でアドレスを1つ足すだけです

## 8. 手順6: 実際に届くか確かめる（いちばん確実な確認）

設定が効いているかは、**テスト応募を1回する**のが最も確実です。

1. スマホなどで `https://yingpin.jp/register` からテスト用の会員を1つ登録する（**実在しない番号は使わないでください。**ご自分の番号で構いません）
2. ログインして求人を1件開き、応募する
3. **オーナーと張海岩さんの両方に**メールが届くか確認する（迷惑メールフォルダも見てください）
4. **祝北辰さんには届いていない**ことを確認する
5. 確認が終わったら、テスト用の会員と応募データを消す（消し方はClaudeに依頼してください）

## 9. よくあるつまずき

| 症状 | 原因 | 対処 |
|---|---|---|
| お二人が `/admin` を開くと「権限がありません」と出る | 職員名簿に入っていない／別のアカウントでログインしている | 第5章の確認SQLで名前が出るか確認。出ていればログアウトして、登録した電話番号で入り直してもらう |
| `violates foreign key constraint` と出る | UIDが違う／ご本人の会員登録がまだ | 第3章・第4章をやり直す |
| `duplicate key value violates unique constraint` と出る | すでに登録済み | そのままで問題ありません。第5章の確認SQLで確認してください |
| `invalid input syntax for type uuid` と出る | UIDのコピーミス（余計な空白や文字） | UIDをコピーし直す |
| 張海岩さんにメールが届かない | 宿題A（ドメイン認証）が未完了 | ダッシュボードの「システム状態」に警告が出ていないか確認 |
| 誰にもメールが届かなくなった | 環境変数を書き換えたときに既存のアドレスを消してしまった | ダッシュボードの「システム状態」で現在の宛先を確認し、第6章で入れ直す |
| アドレスを直したのに反映されない | 再デプロイしていない | 第6章の手順6（Redeploy） |

## 10. あとで必要になったとき

- **退職・異動したら、その日のうちに解除してください。** 解除しない限り、その方は全会員の個人情報を見続けられます。
  - 管理画面の権限: 第5章の `delete from staff_users where id = '…';`（**氏名ではなく必ずUIDで**。同姓同名がいると在籍者の権限まで消えます）
  - 通知メール: Vercelの `STAFF_NOTIFY_EMAILS` からそのアドレスを削除して再デプロイ
  - **2つとも必要です。** 片方だけだと、権限は消えたのに個人情報を含む通知メールが届き続けます
- **誰を・いつ・どちらの操作をしたか**は `docs/ops/db-ledger.md` に記録してください（Claudeに頼めば追記します）

# 登録回数の制限を「本物」にするための設定ガイド（オーナー用・専門知識不要）

> **このガイドの目的**: 新規登録の回数制限を数えておく置き場所（Upstash Redis）を無料で用意し、Vercel に2つの設定値を登録する。所要時間は約15分、1回だけの作業です。（GitHub Issue #30 / PR-3 の後続作業）
>
> **⚠️ やらなくてもサイトは動きます。** 設定しない場合、回数制限は「ゆるい状態」で動きます（下の「やらないとどうなるか」参照）。**β公開の直前までに実施することを推奨**します。
>
> 途中で迷ったら、**いま見えている画面の文字をそのままClaudeに伝えれば**（スクリーンショットでもOK）、その場で案内します。

---

## なぜ必要か（2分で読める背景）

サイトには「同じ電話番号で15分に5回まで」「同じ回線から1時間に30回まで」という新規登録の回数制限を入れました。この**回数を数えておく場所**が必要です。

いまはサイトを動かしているコンピュータの**メモリ（一時的な記憶）**に数えています。ところが、サイトを動かしている Vercel というサービスは、アクセスが増えると**同じサイトを動かすコンピュータを何台も自動で増やします**。

たとえるなら、**受付が複数あって、それぞれが別々のノートに来場者数を書いている**状態です。「5回まで」と決めても、受付が5つあれば合計25回まで通ってしまいます。

Upstash Redis は、その**共通のノート**にあたります。受付が何個に増えても、全員が同じノートに書き込むので「5回まで」が本当に5回になります。

> 💡 **中国からの接続は関係ありません。** このノートを読み書きするのは**サイトのサーバー同士**で、利用者のスマホからは一切アクセスしません。中国で Upstash が見えるかどうかは影響しません。

## やらないとどうなるか（判断材料）

| | 設定しない（いまの状態） | 設定する |
|---|---|---|
| 正常な登録 | 問題なく動く | 問題なく動く |
| 回数制限 | **ゆるい**（上限 × サーバー台数まで通る） | 設計どおり効く |
| 悪意ある大量登録 | ある程度は減らせるが止め切れない | 止められる |
| 費用 | 0円 | **0円**（無料枠の範囲。下記参照） |

**β公開の初期は登録数が少なく、サーバーも1台のことが多い**ため、設定しないまま公開しても即座に事故になるわけではありません。ただし「制限を入れたつもりで実は効いていない」状態は危ないので、**公開前に済ませておく**のが安全です。

## 費用の目安（無料枠で足ります）

- Upstash には**無料プラン（Free / $0）**があります。1日あたり一定回数までのコマンドが無料枠です。
- このサイトが使うのは、**新規登録1回につき数コマンド**だけです。1日100人が登録しても数百コマンド程度で、無料枠に対して非常に小さい量です。
- ⚠️ **申し込み画面でプラン名を必ず確認してください。** 「Free」「$0 / month」と書かれたものを選びます。「Pay as you go」「Pro」などを選ぶ必要はありません。クレジットカードの登録を求められた場合は、**無料枠の範囲で使う旨を確認できるまで進めないでください**（判断に迷ったらClaudeに画面を見せてください）。

## 手順A：Vercel の画面から追加する（推奨・自動で設定値が入る）

Vercel には外部サービスをまとめて追加できる仕組み（Marketplace / Integrations）があり、**この方法だと設定値が自動でサイトに登録される**ため、手作業のコピーが不要です。

1. Vercel にログインし、このサイトのプロジェクトを開きます。
   ```
   https://vercel.com/dashboard
   ```
2. 上部のタブから **Storage**（ストレージ）を開きます。
   - ※画面によっては **Integrations**（連携）や **Marketplace** の中にあります。
3. 一覧から **Upstash**（「Upstash for Redis」等）を選び、**Create / Install**（作成・追加）を押します。
4. プランを選ぶ画面が出たら **Free（$0）** を選びます。
5. データベースの名前を聞かれたら、分かりやすい名前（例: `yingpin-ratelimit`）を入力します。
6. **接続するプロジェクト**を聞かれたら、このサイトのプロジェクトを選んで **Connect**（接続）します。
7. 完了後、**Settings → Environment Variables**（環境変数）を開き、次の2つが自動で追加されているか確認します。
   ```
   UPSTASH_REDIS_REST_URL
   UPSTASH_REDIS_REST_TOKEN
   ```
   - ✅ 両方あればOKです。**手順Cへ進んでください。**
   - ❌ 名前が違うもの（`KV_REST_API_URL` など）しか無い場合は、**手順Bの5番**を見て、同じ値で上の2つの名前を追加してください（名前が違うとサイト側が見つけられません）。

## 手順B：Upstash のサイトから直接申し込む（手順Aが使えない場合）

1. ブラウザで Upstash を開き、アカウントを作ります（GitHubアカウントでのログインが簡単です）。
   ```
   https://upstash.com
   ```
2. **Create Database**（データベースを作成）を押します。
3. 入力・選択するもの:
   - **Name**（名前）: `yingpin-ratelimit`
   - **Type / Primary Region**（場所）: **Japan（東京）またはアジア**を選びます。無ければ一番近い地域で構いません。
   - **Plan**（プラン）: **Free（$0）**
4. 作成すると、データベースの詳細画面に **REST API** という項目があります。そこに次の2つが表示されます。
   - `UPSTASH_REDIS_REST_URL`（`https://...upstash.io` という文字列）
   - `UPSTASH_REDIS_REST_TOKEN`（長い英数字。**パスワードと同じ扱いの秘密の値**）
5. Vercel でこのサイトのプロジェクトを開き、**Settings → Environment Variables** で2つを登録します。
   | Key（名前・そのまま入力） | Value（値） | Environments |
   |---|---|---|
   | `UPSTASH_REDIS_REST_URL` | 上の URL | Production・Preview・Development すべて |
   | `UPSTASH_REDIS_REST_TOKEN` | 上の Token | Production・Preview・Development すべて |
   - ⚠️ **名前は1文字も変えないでください**（大文字・アンダースコアもそのまま）。違うとサイトが見つけられず、設定していないのと同じになります。
6. **Save**（保存）を押します。

> ### 🔐 秘密の値の扱い
> `UPSTASH_REDIS_REST_TOKEN` は**パスワードと同じ**です。チャットやメールに貼り付けないでください（Claudeにも送らないでください）。値が漏れた場合は Upstash の画面で作り直せます。

---

## 手順C：反映させる（重要・忘れやすい）

環境変数は**保存しただけでは反映されません。** サイトを作り直す（再デプロイする）必要があります。

1. Vercel のプロジェクトで **Deployments**（デプロイ）タブを開きます。
2. 一番上（最新）の行の右端にある **…**（点3つ）→ **Redeploy**（再デプロイ）を押します。
3. 確認が出たら **Redeploy** を押し、緑色の完了表示になるまで数分待ちます。

## 設定できたかの確認

サイトの新規登録画面で、**同じ電話番号**で続けて登録を試してみてください。

```
https://yingpin.jp/register
```

1. 適当な未使用の電話番号と、**わざと違うパスワード**を入れて登録を試みます。
2. これを**6回**繰り返します。
3. 6回目に「**登録の試行が続いたため、しばらくお待ちください**」というメッセージが出れば成功です。
   - ※15分待つと解除されます。
   - ※設定しなくてもこのメッセージは出ます（メモリで数えているため）。**設定の有無を画面から見分けることはできません**ので、確認は「手順Aまたは手順Bで2つの環境変数が登録され、再デプロイ済みであること」をもって完了とします。

## よくある質問

**Q. 途中でやめたくなったら？**
A. Vercel の環境変数からこの2つを削除して再デプロイすれば、元のメモリ方式に戻ります。サイトは壊れません。

**Q. Upstash が止まったらサイトも止まりますか？**
A. 止まりません。Upstash に繋がらないときは自動でメモリ方式に切り替わり、登録は続けられます（守りは一時的に弱くなります）。「攻撃されること」より「正規の求職者が登録できないこと」の方が損害が大きい、という判断です。

**Q. Google のサービスではないですか？**
A. 違います。Upstash は独立したサービスで、Google 系サービスの不使用方針（中国アクセス配慮）には抵触しません。

## 用語ミニ辞典

| 英語表記 | 意味 |
|---|---|
| Redis | データを高速に読み書きする置き場所。ここでは「回数を数えるノート」として使う |
| Rate limit | レート制限。一定時間あたりの実行回数の上限 |
| Environment Variables | 環境変数。サイトに渡す設定値（鍵やURLなど）を、コードに書かずに保管する場所 |
| Redeploy | 再デプロイ。サイトを作り直して新しい設定を反映させること |
| Free / Pay as you go | 無料プラン／従量課金プラン。**必ず Free を選ぶ** |
| REST API | ここでは「URLとトークンでデータを読み書きする方式」のこと |

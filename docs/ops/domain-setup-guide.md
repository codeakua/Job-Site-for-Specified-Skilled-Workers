> **補足（ICP備案について）**: 中国国内にサーバーを置く場合は「ICP備案」という中国政府への届出が必要ですが、**このサイトは日本（Vercel）から配信しているので届出は不要**です。その代わり、中国の通信規制の影響は受け得る、という関係になります。

## 1. どんな名前にするか（TLDの選び方）

### 推奨: **`.com`**

| 候補 | 評価 |
|---|---|
| **`.com`** | ✅ **第一候補。** 中国の利用者に最も馴染みがあり、警戒されにくい。中国のSNSやメッセージアプリでリンクを共有する際も自然 |
| `.jp` | △ 日本の企業として信頼感はあるが、中国の求職者には馴染みが薄い。年間費用も `.com` より高め |
| `.app` | △ 常時HTTPS必須で技術的には優秀。ただし中国での知名度が低い |
| `.cn` | ❌ **避ける。** 中国の管理下にあり、法人登記や実名登録などの手続きが必要になる |

> 📌 **実際に取得したのは `yingpin.jp` です（2026-07-29）。** 上の表では `.jp` を「△」としていましたが、**`.jp` は日本の法人しか取得できない信頼性の高いドメイン**であり、有料職業紹介事業者のサイトとしてはむしろ適切です。中国の求職者への馴染みという点だけが `.com` に劣りますが、サービス名（樱聘）とセットで案内するため実害はありません。

### 名前の案

サービス名が **樱聘（YingPin）** なので、`yingpin` を軸にするのが自然です。システム内部でも既に `yingpin.app` という文字列を使っています（会員のログイン処理で内部的に使う架空のアドレス。**実在のドメインである必要はなく、今回買う必要もありません**）。

購入前に空きを確認する候補（上から優先）:
1. `yingpin.com`
2. `yingpin.jp`
3. `yingpin-jobs.com` / `yingpinjob.com`
4. 会社名を軸にした `partner-ssw.com` など（SSW＝Specified Skilled Worker＝特定技能）

> 💡 **ハイフンや数字は避ける**のが無難です（口頭で伝えにくく、打ち間違いが増えるため）。

## 2. どこで買うか（レジストラの選び方）

**結論から: 日本語サポートと請求書対応を重視するなら「Xserverドメイン」または「お名前.com」。コストの安定を重視するなら「Cloudflare Registrar」。**

| 業者 | メリット | デメリット | おすすめ度 |
|---|---|---|---|
| **Xserverドメイン** | 日本語・Whois代行が無料・画面がシンプルで勧誘が少ない・法人の請求書対応 | 取扱いTLDがやや少ない | ⭐ **非技術者に一番おすすめ** |
| **お名前.com** | 日本最大手・日本語サポート・TLDが豊富 | **オプションの勧誘が非常に多く、初期設定で不要な有料サービスにチェックが入っていることがある**。勧誘メールも多い | ⭐ 慣れていれば可 |
| **Cloudflare Registrar** | **更新料が原価のまま上がらない**・Whois代行が標準・セキュリティが堅い | 画面が英語・DNSをCloudflareに預ける必要がある・クレジットカード必須 | 技術者向け |

### ⚠️ 業者選びで一番大事なこと：**「初年度1円」に釣られない**

日本のドメイン業者は**初年度が極端に安く、2年目以降の更新料が高い**ことがよくあります（初年度1円 → 更新料は年間4,000円台、など）。

**必ず「更新料（2年目以降）」を見て比較してください。** `.com` の相場は **年間 1,500〜2,000円程度**です。これより大幅に高い更新料が設定されている場合は他社を検討してください。

### 購入時のチェックリスト

- [ ] **Whois代行（ドメイン情報公開代行）を必ずON** — これをOFFのまま登録すると、**登録者の氏名・住所・電話番号が誰でも見られる状態でインターネットに公開されます**。無料の業者を選ぶか、必ず有効化してください
- [ ] **自動更新をON** — 更新を忘れるとドメインが失効し、サイトが見えなくなるだけでなく、第三者に取得されるリスクがあります
- [ ] **不要な有料オプションのチェックを外す** — 「サーバー同時申込」「SSL証明書」「メールサービス」などは**すべて不要**です（サーバーもSSL証明書もVercelが持っています）
- [ ] **登録者情報は法人名義（株式会社パートナー）で** — 事業用サイトのため。担当者の個人名義にすると退職時などに面倒になります
- [ ] **登録メールアドレスは確実に受信できるもの** — 更新通知や、年1回の**登録者情報の確認メール（これを無視するとドメインが停止されます）**が届きます

## 3. 買ったあとにやること（Claudeが案内します）

> ✅ **この節は [`domain-conoha-vercel-guide.md`](./domain-conoha-vercel-guide.md) に、ConoHa の実画面に沿った具体的な手順として書き直しました。** 以下は流れの概要としてお読みください。

購入が終わったら、**ドメイン名をClaudeに伝えてください。** 以下は流れの説明で、実際の入力値はその時にお伝えします。

### ステップ1: Vercelにドメインを登録する（あなたの操作・約5分）
Vercelの管理画面 → プロジェクト → **Settings → Domains** → 買ったドメイン名を入力して **Add**。
すると Vercel が「DNSにこの値を設定してください」という**指示（A レコード / CNAME レコード）**を画面に表示します。

### ステップ2: ドメイン業者の画面でDNSを設定する（あなたの操作・約10分）
ステップ1で表示された値を、ドメインを買った業者の「DNS設定」画面に入力します。
**この画面のスクリーンショットをClaudeに送っていただければ、どこに何を入れるか1つずつ指示します。**

### ステップ3: 反映を待つ（最大48時間・通常は数分〜数時間）
Vercelの画面のドメイン欄が **「Valid Configuration」（設定OK）** の緑表示に変われば完了です。HTTPS（鍵マーク）の証明書はVercelが自動で取得するので、あなたの作業は不要です。

### ステップ4: 通知メールの送信元を自社ドメインにする（Claudeが案内・約10分）
現在、応募や新規登録のスタッフ通知メールは **Resendのテスト用アドレス（`onboarding@resend.dev`）**から送られており、この状態では**オーナーのアドレス宛にしか届きません**。

独自ドメインが取れたら、Resendにドメインを登録して**SPF・DKIM という認証用のDNS設定**を追加します。これにより:
- スタッフ複数名の宛先にも通知が届くようになる
- 迷惑メールフォルダに入りにくくなる

### ステップ5: 仕上げ（Claudeの作業）
- サイト内のURL表記・法務文書のURL記載を新ドメインに更新
- **HSTS**（一度HTTPSで接続したら以後必ずHTTPSを使わせる設定）をここで初めて安全に導入できます
- 旧 `.vercel.app` のURLから新ドメインへの転送設定

## 4. よくある質問

**Q. サーバーは別に契約しなくていいの？**
A. **不要です。** サイトの本体はVercel、データはSupabaseに既にあります。ドメイン業者からは**ドメイン名だけ**を買ってください。「レンタルサーバーとセットでお得」という案内は、このサイトには不要です。

**Q. メールアドレス（`info@新ドメイン`）は使える？**
A. ドメインを買っただけでは使えません。必要なら Google Workspace 等の契約が別途必要です。ただし**中国からのアクセスを考えるとGoogle系サービスは避ける方針**なので、当面は既存の `@partner-japan.biz` を使い、新ドメインは**サイトと通知メールの送信元専用**にするのがおすすめです。

**Q. 中国語のドメイン（漢字のドメイン）は？**
A. 技術的には可能ですが、**入力しにくく共有時にトラブルが多い**ため推奨しません。

**Q. すでに誰かに取られていたら？**
A. 別の候補に移ってください。「取得済みドメインを買い取る」サービスは高額（数十万円〜）で、交渉も英語のため推奨しません。

## 用語ミニ辞典

| 用語 | 意味 |
|---|---|
| ドメイン | サイトの住所（`example.com`）。年単位でレンタルするもので、買い切りではない |
| レジストラ | ドメインを販売する業者（お名前.com、Xserverドメインなど） |
| TLD | ドメインの末尾（`.com`、`.jp` など） |
| DNS | ドメイン名を、サーバーの場所に変換する仕組み。「住所録」にあたる |
| A レコード / CNAME レコード | DNSに書き込む設定の種類。Vercelが指定する値をそのまま入れる |
| Whois | ドメイン登録者の情報を公開する仕組み。**代行サービスで自分の情報を隠す** |
| SPF / DKIM | 「このメールは本物の送信元から出ている」と証明するDNS設定。迷惑メール判定を避けるために必要 |
| HSTS | 一度HTTPSで接続したブラウザに、以後必ずHTTPSを使わせる設定 |
| ICP備案 | 中国国内にサーバーを置く場合に必要な中国政府への届出。**本サイトは日本配信のため不要** |

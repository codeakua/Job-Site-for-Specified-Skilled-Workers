# 会員データの保管場所を東京へ移す手順（オーナー用・専門知識不要）

> **このガイドでできること**: 会員データを保管している Supabase を、**オーストラリア（シドニー）から東京へ**移します。
> - **所要時間**: 1〜1.5時間（待ち時間を含む）
> - **やる人**: サイトの管理者（Supabase と Vercel にログインできる方）
> - **費用**: かかりません（無料枠のまま）
> - 途中で迷ったら、**いま見えている画面の文字をそのままClaudeに伝えれば**（スクリーンショットでもOK）、その場で案内します。

---

## 1. まず知っておいてほしいこと（2分）

### Supabase は「引っ越し」ができません

Supabase には、**あとから保管場所（リージョン）を変える機能がありません。** プロジェクトは作られた場所に一生留まります。「組織の移動」という機能はありますが、これは保管場所を変えるものではありません。

つまり、**東京に新しいプロジェクトを作り直して、そちらに切り替える**のが唯一の方法です。

### たとえるなら

いまの状態は、**シドニーの貸金庫に会員名簿を預けている**ようなものです。金庫の場所は動かせないので、**東京の支店に新しい金庫を借りて、中身を移し、シドニーの金庫を解約する**——これが今回やることです。

### いまが一番ラクなタイミングです

本番の会員データがまだほとんどありません。**中身がほぼ空の金庫を借り直すだけ**なので、いま move するのが圧倒的に簡単です。会員が増えてから移すと、データの移し替え作業が必要になり、その間サイトを止めることにもなります。

---

## 2. 移す前に：本当に移すべきか（1分で判断）

| | 東京に移す | シドニーのままにする |
|---|---|---|
| 表示の速さ | **速くなる**（日本の利用者で往復が数百ミリ秒縮む） | 遅いまま |
| 法務書類の説明 | **簡単になる**（オーストラリアの法制度の説明が不要になる） | オーストラリアの制度の説明が必要 |
| 中国からのアクセス | 東京の方がやや有利 | — |
| 作業 | 1〜1.5時間必要 | 不要 |

> ⚠️ **ひとつ誤解しやすい点**: 東京に移しても、**「外国の会社に預けている」という事実は変わりません。** Supabase を運営している Supabase, Inc. はアメリカの会社だからです。個人情報保護法の「外国にある第三者への提供」は、**サーバーの置き場所ではなく、預け先の会社がどこの国の会社か**で判断されます。
>
> 東京に移して軽くなるのは、**「外的環境の把握」**（＝データが実際に置かれている国の法制度を調べて対策する義務）の部分です。これは弁護士への確認論点 A-1・A-6 に含めてあります。

**結論**: 速度と書類の簡潔さの両方で得なので、**移すことをおすすめします。**

## 3. 準備：いまのリージョンを確認する（3分）

まず、本当にシドニーなのかを**あなたの目で確認**してください。Claude はサーバーの接続先から推測しましたが、公式画面での裏取りがまだです。

1. ブラウザで下のURLを開きます（Supabase にログインした状態で）。
   ```
   https://supabase.com/dashboard/project/jqevswrbdbmxifauqhfi/settings/general
   ```
2. **Region**（リージョン）という欄を探します。
3. そこに何と書いてあるかを確認します。

| 表示 | 意味 | どうする |
|---|---|---|
| `Southeast Asia (Sydney)` / `ap-southeast-2` | オーストラリア | **このガイドを続けてください** |
| `Northeast Asia (Tokyo)` / `ap-northeast-1` | すでに東京 | **移設は不要です。** Claude に伝えてください（法務書類の記載を東京に直します） |
| それ以外 | 別の国 | Claude にその文字を伝えてください |

## 4. 移す前の確認：消えて困るデータはありますか（5分）

新しいプロジェクトは**空の状態から始まります**。求人データはリポジトリのSQLから復元できますが、**会員が登録した情報とスタッフのログイン情報は自動では移りません。**

1. 管理画面 `/admin/members` を開き、**会員が何人いるか**を数えます。
2. 下の表で進め方を選びます。

| 会員の状況 | 進め方 |
|---|---|
| **テスト登録だけ（実在の求職者がいない）** | **このガイドのとおり作り直す**のが一番簡単・確実です |
| **実在の求職者が数人いる** | その方々に「もう一度登録をお願いします」と連絡できるなら、作り直しで問題ありません |
| **実在の求職者が多数いる** | データを移す作業が必要です。**Claude に「会員データを引き継ぎたい」と伝えてください**（手順が変わります） |

> 💡 会員のパスワードは、**Claude にも Supabase の管理画面にも見えない形**（ハッシュ化）で保管されています。作り直す場合、会員には再登録をお願いすることになります。

## 5. 手順

### ステップ1：東京に新しいプロジェクトを作る（10分＋待ち時間）

1. https://supabase.com/dashboard を開きます。
2. **「New project」**（新しいプロジェクト）を押します。
3. 次のとおり入力します。

   | 項目 | 入力する内容 |
   |---|---|
   | Name（名前） | `yingpin-tokyo`（分かる名前なら何でも可） |
   | Database Password | **「Generate a password」を押して自動生成**し、**必ずコピーしてメモ帳などに保存**してください。あとから見ることはできません |
   | **Region** | **`Northeast Asia (Tokyo)`** ← **ここが今回の目的です。間違えないでください** |
   | Plan | Free（無料）のまま |

4. **「Create new project」**を押します。
5. 準備が終わるまで**2〜5分**待ちます（画面に進み具合が出ます）。

> 💡 無料プランでは**プロジェクトを2つまで**持てます。いまのシドニーのものを残したまま東京のものを作れるので、**失敗しても元に戻せます。**

---

### ステップ2：データベースの中身を作る（10分）

1. 新しいプロジェクトの画面で、左メニューの **「SQL Editor」** を開きます。
2. パソコンでリポジトリの **`app/supabase/setup.sql`** をテキストエディタで開き、**中身をすべて選択してコピー**します（755行あります）。
   - GitHub から開く場合: リポジトリの `app/supabase/setup.sql` → 右上の「Raw」→ 全選択してコピー
3. SQL Editor に貼り付けて、右下の **「Run」** を押します。
4. **`Success. No rows returned`** と出れば成功です。

> このファイルは**何度実行しても安全**に作られています。エラーが出たら、**その文字をそのまま Claude に伝えてください。**

**確認**: 左メニューの「Table Editor」を開き、`members` `jobs` `applications` `favorites` `fields` `staff_users` の6つの表があること、`jobs` にサンプル求人が入っていることを確かめます。

---

### ステップ3：認証のセキュリティ設定をやり直す（15分）

⚠️ **この設定は新しいプロジェクトには引き継がれません。必ずやり直してください。** 忘れると、`1234` のような弱いパスワードで登録できてしまいます。

**`docs/ops/supabase-auth-policy-guide.md`** の手順を、**新しいプロジェクトに対して**もう一度実行します。設定するのは次の3つです。

1. パスワードの最低文字数（8文字以上）を強制する
2. 漏洩パスワードの拒否をONにする
3. ログイン試行回数の制限を確認する

> 🚨 **「Confirm email」（メール確認）は絶対にONにしないでください。** このサイトは電話番号でログインする仕組みで、内部的に `@phone.yingpin.app` という架空のメールアドレスを使っています。ONにすると**新規登録が全員できなくなります。**
>
> ガイドに書かれているURLは古いプロジェクトのものです。`jqevswrbdbmxifauqhfi` の部分を、**新しいプロジェクトのID**に読み替えてください（新しいIDは、新プロジェクトを開いたときのURLに出ています）。

---

### ステップ4：スタッフを登録し直す（社員1人あたり10分）

管理画面 `/admin` を使う社員を、**新しいプロジェクトに登録し直します。**

**`docs/ops/staff-registration-guide.md`** の手順を、新しいプロジェクトに対して実行してください。

---

### ステップ5：サイトの接続先を切り替える（15分）

ここまでは**サイトに影響しません**。ここからが切り替えです。

**5-1. 新しい接続情報を控える**

1. 新しいプロジェクトで **Project Settings → API** を開きます。
2. 次の2つをコピーしてメモします。
   - **Project URL**（`https://〇〇〇.supabase.co` の形）
   - **anon public** キー（`eyJ...` で始まる長い文字列）

**5-2. Vercel の設定を書き換える**

1. https://vercel.com/dashboard を開き、このサイトのプロジェクトを選びます。
2. **Settings → Environment Variables** を開きます。
3. 次の2つを、**5-1でコピーした新しい値に書き換え**ます（Edit → 値を貼り替え → Save）。

   | 名前 | 新しい値 |
   |---|---|
   | `NEXT_PUBLIC_SUPABASE_URL` | 新しい Project URL |
   | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 新しい anon public キー |

   > その他（`RESEND_API_KEY`・`STAFF_NOTIFY_EMAILS`・`UPSTASH_...`）は**そのままで構いません。**

**5-3. 再デプロイする（← これを忘れると切り替わりません）**

⚠️ **環境変数を保存しただけでは、いま動いているサイトには反映されません。**

1. **Deployments** タブを開きます。
2. 一番上（最新）の行の右端の **「⋯」** → **「Redeploy」** を押します。
3. 確認画面で **「Redeploy」** を押し、完了（緑のチェック）まで**1〜3分**待ちます。

---

### ステップ6：動作確認（10分）

**旧プロジェクトを消す前に**、必ず次を全部確かめてください。

1. サイトを開き、**求人一覧が表示される**（＝新しいDBを読めている）
2. **テスト用に新規会員登録してみる**（＝書き込めている）
   - このとき通知メールが届くことも確認できます
3. その会員でログインし、**求人に応募できる**
4. `/admin` にスタッフでログインし、**いま登録した会員と応募が見える**

> 会員として既にログインしていた場合、**切り替えで一度ログアウトされます**（保存場所が変わるため）。これは正常です。

**うまくいかないとき**は、旧プロジェクトの値に戻して再デプロイすれば元に戻せます。慌てずに、画面に出ているエラーを Claude に伝えてください。

---

### ステップ7：あと片付け（5分）

**ステップ6が全部OKだった場合のみ**行ってください。念のため**1週間ほど空けてから**でも構いません。

1. 旧プロジェクト（シドニー）の Project Settings → General → 一番下の **「Delete project」** から削除します。
2. Claude に **「東京への移設が終わった」** と伝えてください。次の3つを直します。
   - 法務書類（プライバシーポリシー第6条・第7条、レビュー依頼書）の**保管国をオーストラリア→日本に変更**し、PDFを作り直す
   - `docs/ops/supabase-auth-policy-guide.md` に書かれている**古いプロジェクトIDの差し替え**
   - `docs/progress.md` への記録

## 6. つまずきやすいところ

| 症状 | 原因と対処 |
|---|---|
| サイトが「求人が取得できません」と出る | ステップ5-3の**再デプロイを忘れている**ことがほとんどです |
| 新規登録すると必ず失敗する | ステップ3で **Confirm email を誤ってONにした**可能性。OFFに戻してください |
| 管理画面に入れない | ステップ4のスタッフ登録が済んでいません |
| Region に東京が出てこない | 「New project」の作成中しか選べません。**作成後は変更できない**ので、間違えたらプロジェクトを削除して作り直してください |
| Database Password を控え忘れた | 通常の運用では使いません。必要になったら Project Settings → Database から再設定できます |

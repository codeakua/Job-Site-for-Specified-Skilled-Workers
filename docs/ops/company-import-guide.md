# 企業管理（求人企業マスタ）の導入手順書（オーナー向け）

最終更新: 2026-08-03（T-19 企業→求人の自動作成・公開状態・情報不足アラートを追記。導入自体は 2026-08-02 に完了済み）

## これは何をする機能か

- パートナー協同組合の**企業データベース（約100社）をサイトに登録**し、管理画面に「🏢 企業管理」を追加します
- **求人票に「どの企業の求人か」を紐づけられる**ようになります（求人一覧・応募一覧にも企業名が出ます）
- 企業一覧は**CSVでダウンロード**でき、Excelでそのまま開けます（文字化けしません）
- 各企業には、組合の**雇用条件書データベース由来の実際の労働条件**（月給・手取り・控除・休日数・寮の家賃など）も参考値として入っています

> 🔒 **会員側（求人サイト）には一切表示されません。** 企業テーブルはスタッフだけが読める設定（RLS）で、会員がブラウザから直接データベースに問い合わせても**1行も見えません**（ローカル環境で実証済み）。求人票の見た目は今までと同じ「匿名の企業プロフィール」のままです。

## 適用手順（3ステップ・順番が大事）

> ⚠️ **必ず「SQL → データ投入 → マージ」の順で行ってください。**
> 新しいアプリは企業テーブルを読みに行くため、SQLより先にマージすると、SQLを流すまでの間だけ管理画面の求人一覧が表示できなくなります。

### ① 0006 のSQLを実行する（テーブルを作る）

1. Supabase の **SQL Editor** → **+ New query**
2. `app/supabase/migrations/0006_companies.sql` の中身をすべてコピーして貼り付け → **Run**
3. 確認クエリを実行して、期待値どおりか確認：

```sql
select
  (select count(*) from information_schema.tables
     where table_schema='public' and table_name='companies')                     as "① 企業テーブル(期待値 1)",
  (select count(*) from pg_policies where schemaname='public')                   as "② アクセス制御ルール(期待値 16)",
  (select count(*) from pg_policies
     where schemaname='public' and tablename='companies')                        as "③ 企業のルール(期待値 1)",
  (select count(*) from information_schema.columns
     where table_schema='public' and table_name='jobs'
       and column_name='company_id')                                             as "④ 求人の紐づけ列(期待値 1)";
```

→ **1 / 16 / 1 / 1** になれば成功。

### ② 企業データの投入SQLを実行する

1. Claudeからチャットで受け取った **`import_companies.sql`** の中身をすべてコピーして、SQL Editor に貼り付け → **Run**
   - このファイルは**実在の企業名・個人名を含むため、GitHubリポジトリには置いていません**（チャットでの受け渡しのみ）
   - **誤って2回実行しても大丈夫**です（同じ社名は追加されない作り ＝ `on conflict do nothing`）。あとから管理画面で修正した内容が上書きされることもありません
2. 確認：

```sql
select count(*) from companies;
```

→ 受け渡し時に伝える**期待件数**と一致すれば成功。

### ③ PRをマージする（画面が使えるようになる）

マージ＝デプロイ後、以下を実機で確認：

1. `/admin` を開く → サイドバーに **「🏢 企業管理」** がある／ダッシュボードに **「登録企業」** の枚数が出る
2. **企業管理** を開く → 全社が一覧に出る。検索（社名・担当者など）と絞り込み（契約状況・受入業種）が効く
3. **「⬇ CSVダウンロード」** → Excelで開いて日本語が化けていない・全社入っている
4. **求人管理 → 求人を編集** → 「企業情報」セクションの **「求人企業」** で企業を選んで保存 → 求人一覧の「企業」列に社名が出る
5. **応募管理** → 求人名の下に企業名（🏢）が出る（企業を紐づけた求人への応募のみ）
6. **会員側の確認**: 求人一覧・求人詳細に企業名が出ていないこと（今までどおり匿名プロフィールのみ）

## ④ 企業→求人の自動作成と公開（2026-08-03 追加・T-19）

企業管理に登録した企業から、**求人の下書きが自動で作られる**ようになりました。企業の雇用条件データ（職種・就業場所・月給・休日・寮など）が求人票に流し込まれます。オーナーの作業は次の2つです。

### ④-1 サンプル求人14件を削除する（SQL・1回だけ）

開発時に入れた架空のサンプル求人（id 1〜14）を消します。Supabase の **SQL Editor** で:

```sql
-- 事前確認: サンプル求人に紐づく応募・お気に入りの件数（テスト分だけのはず）
select
  (select count(*) from applications where job_id between 1 and 14) as sample_apps,
  (select count(*) from favorites    where job_id between 1 and 14) as sample_favs;

-- 削除（上記の応募・お気に入りも一緒に消えます = テストデータのみ）
delete from jobs where id between 1 and 14;

-- 確認: 0 になれば成功
select count(*) from jobs where id between 1 and 14;
```

実施したら `docs/ops/db-ledger.md` の記録欄に日付を書き込んでください。

### ④-2 「求人下書きを一括作成」ボタンを押す

1. 管理画面 → **企業管理** を開くと、右上に **「📝 求人下書きを一括作成（◯社）」** ボタンが出ています（求人が無い企業がある間だけ表示されます）
2. 押すと、求人が無い**全企業に下書き求人が1件ずつ**作られます（約100社なら約100件）。何度押しても増えません
3. ダッシュボードの「下書きの求人」が一気に増えますが、**下書きは会員側には見えない**ので安心してください

### ④-3 公開のしかた・画面の見方

- 企業一覧の **「公開状態」** 列: **公開中**（会員側に求人が出ている）／**非公開中**（下書きのみ）／**求人未作成**
- 社名の横に **「⚠ 情報不足」** が付いている企業は、職種・勤務地・月給・受入業種の分野など、**公開に必要な情報が足りません**。マウスを乗せると理由が表示され、社名をクリックした編集画面ではより詳しい一覧（必須の不足＋改善するとよい点）が見られます
- 情報が足りている企業は、一覧の **「公開」ボタン**で会員側に公開できます（**「停止」**で非公開に戻せます）。情報不足の企業は公開ボタンが押せません → 企業情報を補完して保存するか、求人管理で求人を直接編集してください
- 自動作成された求人は日本語が中心です。**中国語訳が未入力の部分は、会員側では日本語がそのまま表示されます**（協議のうえ「必須情報が揃えば公開可・翻訳は順次改善」の方針）。翻訳は求人管理の編集画面（日本語｜中文の左右ペア）で入れられます

> ⚠️ **企業情報をあとから修正しても、作成済みの求人には自動反映されません**（スタッフが求人側で磨いた内容を守るため）。求人の内容を変えたいときは求人管理から編集してください。

## ふだんの使い方

- **新しい企業が組合に加入したら**: 企業管理 → 「＋ 新規登録」で追加（社名だけでも保存できます）。**保存すると下書き求人も自動で1件作られます**
- **求人票を作るとき**: 基本は自動作成された下書きを求人管理で磨いて公開するだけ。手動で追加の求人を作る場合は、求人フォームの「求人企業」でその企業を選べば紐づきます。企業の編集画面には「この企業の求人」一覧と不足チェックも出ます
- **企業情報を直したいとき**: 一覧から社名をクリックして編集。労働条件・賃金の欄は**雇用条件書からの自動抽出値（参考）**なので、間違いを見つけたら原本（雇用条件書）を確認のうえここで修正してください
- **契約状況を見たいとき**: 一覧の列は「公開状態」に置き換わりました。契約状況は**企業の編集画面（見出しの下）とCSV**で確認できます
- **削除ボタンはありません**: 契約が終わった企業は「契約状況」欄を書き換え、一覧の「停止」で求人を非公開にして残します（求人票との紐づけ履歴を守るため）。どうしても消す場合はSQLで削除でき、その企業に紐づいていた求人は「企業未設定」に戻るだけで消えません

## 注意（データの性質）

- 電話番号・メールアドレスの欄は**元データに無いため空**です。分かり次第、編集画面で入力してください
- CSVをExcelで開くと、**先頭が0の電話番号は0が消えて見える**ことがあります（Excelの表示仕様。データ自体は壊れていません）
- 労働条件の数値は契約書からの自動抽出のため、**まれに抽出ミスがあります**（元のExcelにも「最終確認には元書面をご参照ください」と注記があります）

## 再取込について（将来）

組合の企業データベースが大きく更新されたときは、Claudeに「企業データを取り込み直したい」と伝えてください。**同名企業は追加されない仕組み**のため、新規加入企業だけが追加されます（既存企業の一括更新が必要な場合は、その時点で専用のSQLを別途作ります）。SQLで追加した企業には求人が付かないので、投入後に**「求人下書きを一括作成」ボタンを1回押してください**。

> ⚠️ **企業を全部消してから入れ直す場合の順序**（通常は不要。やる前にClaudeに相談を）:
> ①自動作成された下書き求人を先に削除（`delete from jobs where company_id is not null and status = 'draft';`）→ ②companies を削除 → ③再取込 → ④一括作成ボタン。
> 順序を間違えると、企業が消えた「企業未設定」の下書き求人が残り、再取込後に求人が二重にできます。
